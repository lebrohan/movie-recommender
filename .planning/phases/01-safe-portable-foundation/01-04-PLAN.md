<objective>
Phase goal (ROADMAP, verbatim): A developer can clone the repo, configure it through environment variables, and run every pipeline stage from any directory with no credentials or personal data in git, CI protecting the code, and a faster IMDb load and embed.

This plan delivers reproducible installs (HYG-03, Claude's Discretion: exact pip-freeze pins, requirements-dev.txt split), true run-from-any-directory via a minimal editable install (HYG-04), and CI on every push (TEST-02). The workflow file is written and its commands proven locally here; it first runs on GitHub when plan 01-07 publishes the rewritten history, and that plan observes the result.

Discretion choices made here (documented for the checker):
- CI matrix = the lowest Python minor that every pin supports (3.11 per CONTEXT unless a pin needs newer) plus 3.14 (the interpreter this machine actually uses).
- Lint: a `python -m compileall -q backend tests` syntax gate, no linter package (no new dependency to vet).
- DB integration tests get a throwaway `pgvector/pgvector:pg16` service container with trust auth, so no credential appears in the workflow (HYG-01). `TEST_DB_DSN` is a test-harness variable, not an app setting, so per D-08 it is documented in README and tests, not in .env.example.
- Top-level pins match the versions in this machine's global `py -3.14` environment where present (pandas 3.0.6, numpy 2.5.3, SQLAlchemy 2.1.1, ollama 0.6.3, requests 2.34.2, beautifulsoup4 4.15.0, lxml 6.1.3, openpyxl 3.1.5 at plan time), because that environment built the stored text blobs; psycopg2-binary uses the version matching the installed psycopg2 (2.9.13) when a binary wheel exists; tqdm, python-dotenv and pytest use the latest release.

Output: pinned requirements.txt and requirements-dev.txt, pyproject.toml, .github/workflows/ci.yml, README setup section. Plan 01-01 installed python-dotenv into .venv but did not edit requirements.txt; this plan adds it as an exact pin.

Wave-2 ordering: plans 01-02, 01-03 and 01-04 touch disjoint files but share the git index and the shared `.venv`. Run them one after another in the main checkout (order 01-02, 01-03, 01-04), or each in its own git worktree, with 01-04's `.venv` resync done only after its worktree merges.
</objective>

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-13 | Tampering | unpinned/transitive dependency drift | medium | mitigate | Complete pip-freeze pins including transitive packages; CI installs only from those files. |
| T-01-14 | Elevation of Privilege | GITHUB_TOKEN scope in CI | medium | mitigate | `permissions: contents: read`; no secrets used; only first-party actions/checkout and actions/setup-python. |

| T-01-16 | Tampering | DB tests touching a real database | medium | mitigate | Tests read only TEST_DB_DSN (never DB_DSN) and isolate in a throwaway schema (plan 01-05); README states it must be disposable. |
| T-01-SC | Tampering | pip installs | high | mitigate | New packages approved at the plan 01-01 legitimacy gate; exact pins; psycopg2-binary name checked. |
