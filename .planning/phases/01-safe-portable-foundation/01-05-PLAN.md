<objective>
Phase goal (ROADMAP, verbatim): A developer can clone the repo, configure it through environment variables, and run every pipeline stage from any directory with no credentials or personal data in git, CI protecting the code, and a faster IMDb load and embed.

This plan makes IMDb loading faster (PERF-04, load half) without changing a single byte of the embedded text (D-13) and without re-embedding unchanged films (D-12). The load now reads title.basics in chunks with explicit dtypes, builds blobs with vectorized string ops, and writes the staging table with COPY (D-14). A full-dataset old-vs-new comparison gates the change. The embed half and the before/after timing run are plan 01-06.

Discretion choice: the staging insert switches from `to_sql(method="multi")` to PostgreSQL COPY via pandas' documented `method=` callable (psycopg2 `copy_expert`), because multi-row INSERT is the slowest part of a large reload. The staging -> movies upsert SQL stays exactly as it is.

Entry-point order (same as plans 01-01 and 01-03): `use_utf8_console()` first, then the argparse parser and `parse_args()`, then `get_db_dsn()` immediately after `parse_args()`.

Output: refactored load_imdb.py, db_engine fixture, a local disposable movies_test database, tests/test_load_imdb.py, the full-dataset MISMATCHES=0 result in the SUMMARY.
</objective>
