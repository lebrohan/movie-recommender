<objective>
Phase goal (ROADMAP, verbatim): A developer can clone the repo, configure it through environment variables, and run every pipeline stage from any directory with no credentials or personal data in git, CI protecting the code, and a faster IMDb load and embed.

This plan is the phase tracer: one real path from a repo-root `.env` through `backend/config.py` into a pipeline stage (`setup_db`), proven by pytest, then expanded to every DB stage. It does four things:
- removes the hardcoded DSN (HYG-01);
- makes configuration environment-driven (OPS-02, D-06, D-07, D-08), reading `.env` lazily so importing config has no side effects (HYG-05);
- makes config resolution independent of the working directory (HYG-04 part, D-09);
- clears the package-legitimacy gate for every new package the phase installs.

Design note (revision 1): `.env` is never loaded into `os.environ`. Settings are resolved at call time by getters: the real environment first, then a cached `dotenv_values()` read of `<repo root>/.env`, then the default. Real environment variables always win (D-07), and importing `backend.config` is pure. Module-level settings constants (other than `EMBED_DIM`) become getters, so call sites in load_imdb, embed, match and utils change too.

Entry-point order used by every plan in this phase: `use_utf8_console()` first (added in plan 01-03), then the argparse parser and `parse_args()`, then `get_db_dsn()` immediately after `parse_args()`.

Purpose: every later plan (hygiene, side-effects, pins/CI, load, embed, history rewrite) builds on these getters, the repo-root `.env`, the `.venv` and the pytest scaffold created here.
</objective>
