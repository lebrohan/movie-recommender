<objective>
Phase goal (ROADMAP, verbatim): A developer can clone the repo, configure it through environment variables, and run every pipeline stage from any directory with no credentials or personal data in git, CI protecting the code, and a faster IMDb load and embed.

This plan purges personal data and the leaked DB password from ALL history, on every ref (D-01). It also sets up and verifies the GitHub remote, publishes, and observes the first CI run.

Facts that override 01-CONTEXT.md D-02: origin already exists (https://github.com/lebrohan/movie-recommender.git), and its main branch (eda61f2 at plan time) is already pushed with the CSV/XLSX and the password in history. Publishing therefore needs a force-push or a delete/recreate. That step is one-way and outward-facing: the executor never pushes; the user does. At plan time the only local remote-tracking ref is origin/main, but GitHub may hold other branches, tags or refs/pull/*, so every remote ref is enumerated and audited at execution time.

Stale `refs/original/*` refs from an earlier filter-branch also keep old history reachable locally. All purges go into ONE rewrite and ONE atomic publish. The rewrite changes every commit hash, including the GSD planning commits; SHAs quoted in earlier SUMMARYs become stale (map: .git/filter-repo/commit-map).

Fixed work directory, outside the repo: `C:/Users/Rohan/movie-recommender-rewrite-work` (called WORK below). It holds the ref lists, the audit clones and replacements.txt. It is deleted at the end of Task 3 because it contains the old secret and old data.

NEVER write the old password literal into any tracked file, commit message, plan or SUMMARY.

Ignored files on disk (imdb_data/, graphify-out/, the Letterboxd exports, recommendations.csv, .env) are NOT in the mirror backup, which holds history only. Never run `git clean -x`, never delete them, and keep the precondition that they are untracked at HEAD, so the rewrite's reset leaves them alone.
